## When to Use

- Запрос вида «о чём видео», «о чём ролик», «что в этом видео», «кратко содержание
  видео» — в любом близком по смыслу wording'е — со ссылкой на видео.
- Ссылка + дополнительные вопросы к видео в одном запросе («о чём видео и как там
  настроить X?») — отвечать и на них по транскрипту.
- DON'T use for: «скачай видео» без пересказа (чистый yt-dlp), «распознай аудио,
  где ссылку уже дали раньше» (чистый mlx-whisper), живые стримы.

# Video Summary («о чём видео»)

Триггер: пользователь пишет «о чём видео / о чём ролик / кратко содержание» или
подобный по смыслу вопрос и прикладывает ссылку на видео (YouTube и любые сайты
yt-dlp). Плюс: если в том же запросе есть дополнительные вопросы к видео — ответить
и на них.

Это оркестратор над двумя скиллами — строго в этом порядке:

1. `media/yt-dlp` — скачать аудио
2. `media/mlx-whisper` — распознать речь в текст

## Procedure

1. **Загрузить оба скилла** (`skill_view media/yt-dlp`, `skill_view media/mlx-whisper`) и следовать их процедурам. Ниже — только склейка и гейты.

2. **Метаданные ДО скачивания** (это и шаг детекта языка):
   ```bash
   ~/.local/bin/yt-dlp --js-runtimes node --skip-download \
     --print "%(title)s | %(uploader)s | %(duration)s сек | %(view_count)s | %(description).500B" <URL>
   ```
   По заголовку/описанию определить язык речи (гейт шага 4 скилла mlx-whisper:
   источник языка должен быть называемым — «заголовок EN», либо детект на 30 с).
   Привычка/дефолт «ru» запрещены — видео бывает на любом языке.

3. **Скачать аудио** (обычный путь, mp3 в result-yt-dlp):
   ```bash
   python3 ~/.hermes/skills/media/yt-dlp/scripts/download_dated.py --audio <URL>
   ```

4. **Транскрибировать** (длинные файлы — только `terminal(background=true)` +
   `process wait`; скилл mlx-whisper: VAD+STT+LLM-коррекция, ~7 мин на 40-мин аудио):
   ```bash
   ~/.local/share/uv/tools/mlx-whisper/bin/python \
     ~/.hermes/skills/media/mlx-whisper/scripts/vad_transcribe.py "<mp3>" \
     --language <detected> \
     --terms "<имена/термины из заголовка и описания через запятую>"
   ```
   `--terms` — имена/термины из заголовка и описания через запятую: LLM-этап
   исправляет их написание в транскрипте (баг UnboundLocalError при пустом
   LLM-этапе уже исправлен, коммит 527c906 — без `--terms` скрипт тоже работает).

5. **Прочитать MD-результат целиком** (`read_file`) из `~/result-mlx-whisper/`.

6. **Ответ пользователю** (в end-to-end структуре, на языке запроса юзера):
   - **Краткое содержание** — сюжеты/тезисы в порядке появления, с опорой на таймстампы; длину сообразно длительности и насыщенности видео (не дутьё).
   - **Выводы** — что из этого следует практически; отличать выводы автора от своих собственных (помечать).
   - **Ответы на дополнительные вопросы из запроса** — отдельным блоком, цитируя конкретные места транскрипта (по таймстампу), а не пересказ.
   - Если что-то в транскрипте распознано ненадёжно (имена, термины, «каша») — сказать прямо и указать, на какие фрагменты это влияет.

## Pitfalls

- **Язык — гейт**: инцидент 2026-09-02 — 39-мин английское видео прогнали с
  `--language ru` «по привычке» → полкаша и полный перезапуск. Источник языка
  называть явно; сомнение → детект на первых 30 с.
- Метаданные считать до скачивания: они же дают title для `--terms`.
- Стиль ответа: юзер не любит многобукв — содержание плотное, без воды; но не
  жертвовать сюжетными поворотами ради краткости.
- Оба артефакта (mp3 + MD) остаются в `~/result-yt-dlp/` и `~/result-mlx-whisper/` —
  когда юзер потом задаёт доп. вопросы по видео, отвечать по сохранённому
  транскрипту без повторной транскрипции.
